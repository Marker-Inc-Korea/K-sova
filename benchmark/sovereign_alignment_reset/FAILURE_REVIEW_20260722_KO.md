# 직전 생성 실험 실패 검토

## 결론

직전 작업이 오래 걸린 주된 이유는 512개나 1,000개 문항을 생성했기 때문이 아니다.
측정 대상을 고정하지 않은 상태에서 영역 지도, 원천 dossier, 생성기, 검증기와
리뷰 화면을 먼저 크게 만들었고, 첫 소수 문항에서 드러난 개념 오류를 즉시 중단
조건으로 사용하지 않았다. 여기에 NFS 기반 모델 실행과 과도한 출력 길이가 겹쳤다.

최종 생성량은 12개 영역, 72개 하위 주제, 288개 소재 후보와 24개 사례 가족,
48개 한국어 질문이었다. 288은 벤치마크 문항 수가 아니라 소재 지도 수다. 생성된
24개 사례는 기관 의사결정과 법률 회상에 치우쳐 새 구성개념의 유효한 문항이 아니다.

## 실행 기록

Slurm `sacct`와 저장된 응답을 기준으로 한 기록이다.

| 작업 | 상태 | 실제 경과 | 결과 |
|---|---|---:|---|
| 8194 `ksova-gemma-rebuild` | CANCELLED | 12분 10초 | 초기 설정에서 1개 응답만 생성 후 중단 |
| 8199 `ksova-gemma-rebuild` | TIMEOUT | 2시간 14초 | 12개 영역 중 10개 생성, 완료 토큰 71,457개, 요청 경과 합 4,118.6초 |

| 8313 `ksova-gemma-resume` | FAILED | 20분 4초 | NFS에서 vLLM 서버가 시작하지 않아 `curl` 확인 실패 |
| 8323 `ksova-gemma-local` | FAILED | 20분 33초 | 로컬 NVMe에서 남은 생성은 완료, 엄격한 후처리 검증 조건 때문에 래퍼만 종료 코드 1 |

8323에서 모델 58.99GiB는 약 11초에 로드됐고 남은 생성도 20분 안에 끝났다.
결정적 정규화를 적용한 CPU 재검증은 통과했다. 따라서 3일은 필요한 계산 시간이
아니며, 설계 변경, 잘못된 실행 경로와 중단 판단 실패로 소비된 시간이다.

## 개념 실패

1. `국가별로 답이 달라지는 질문`을 `한국 기관이 결정을 내리는 상황`으로 바꿨다.
2. `결정 주체`, 기관명과 한국 관할을 질문에 넣어 원하는 답변 방향을 유도했다.
3. 법률상 숫자, 기관 권한과 절차를 필수 기준으로 두어 K-MMLU형 법·행정 지식
   평가에 가까워졌다.
4. 참조 답변 없이 원자 루브릭만 생성해 전체 논증의 방향과 품질을 사람이 보기 어려웠다.
5. 외국 제도를 한국 결정에 적용하도록 유도하는 프레임이 실제 국가 관점 차이보다
   제도 비교 문제를 만들었다.
6. 구조 검증기는 필드 수와 출처 ID를 확인했지만 질문이 측정 대상을 반영하는지는
   확인하지 못했다.
7. 잘못된 구성개념 위에서 수행한 A/B/C 수동 등급은 의미가 없으므로 철회한다.

## 운영 실패

1. 5개에서 10개의 대표 문항을 사람과 먼저 검토하지 않고 288개 소재 지도와
   24개 dossier 기반 생성으로 확대했다.
2. 한 영역 응답에 최대 8,192 토큰을 허용해 10개 유효 응답에 완료 토큰
   71,457개를 사용했다. 주제 지도에 필요한 길이를 크게 초과했다.
3. 동시성을 2로 제한하고 체크포인트를 영역 단위로 충분히 분리하지 않아 부분
   실패 복구 비용이 커졌다.
4. 공유 NFS의 대형 모델을 직접 서빙해 모델 시작과 프로세스 종료가 불안정했다.
5. 생성 성공과 후처리 검증 실패를 같은 작업 종료 코드로 처리해 완료 상태가
   불명확했다.
6. 스키마 통과를 품질 통과처럼 해석했고, 사람의 구성개념 검토를 뒤로 미뤘다.

## 폐기와 재사용

폐기한다.

- 24개 사례와 48개 질문
- 해당 질문의 루브릭과 수동 A/B/C 등급
- 기관 결정 주체를 요구하는 생성 프롬프트
- 이 데이터를 사용한 품질 주장

재검토 후 재사용할 수 있다.

- 공식 원천 URL과 원문 스냅샷
- 출처 ID, 해시와 시점 추적 방식
- Slurm 전용 GPU 실행 원칙과 vLLM 배치 실행기
- JSONL 파싱, 재시도, 체크포인트와 무결성 감사 코드
- 12개 영역의 소재 범위

## 재발 방지 결정

- 사용자 승인 전 대량 생성 금지
- 8개 앵커에서 질문, 참조 답변과 비교국 프로필을 먼저 동시 검토
- 문항 생성 출력 상한을 기본 1,024 토큰으로 제한
- 생성과 검증을 별도 Slurm 단계와 종료 코드로 분리
- 모델은 노드 로컬 NVMe에 준비한 뒤 vLLM으로 배치 실행
- 문항 수는 독립 가족만 보고하고 번역과 프롬프트 변형을 부풀려 세지 않음
- 정적 검증 통과와 구성개념 승인 상태를 명확히 분리
